In this edition we feature the EKS Provisioned Control Plane 99.99% SLA and new 8XL scaling tier, the Amazon EKS Hybrid Nodes gateway for simplified hybrid networking, new IAM condition keys for cluster governance, Neuron and EFA support for Dynamic Resource Allocation, managed node group warm pools for faster scale-out, one-click cluster access via CloudShell, and the Kubernetes v1.36 "Haru" release along with Gateway API v1.5 reaching stable.

## New AWS services and features

* [Amazon EKS announces 99.99% SLA and new 8XL scaling tier for Provisioned Control Plane clusters](https://aws.amazon.com/about-aws/whats-new/2026/03/amazon-eks-announces-sla-8xl-scaling-tier/)
  * Amazon EKS now offers a 99.99% SLA for clusters running on Provisioned Control Plane, up from the previous 99.95% SLA on standard control plane.
  * The new 8XL scaling tier doubles the API request processing capacity of the previous largest tier, designed for ultra-scale AI/ML training, large-scale data processing, and mission-critical workloads requiring guaranteed control plane responsiveness.

* [Introducing the Amazon EKS Hybrid Nodes gateway for hybrid Kubernetes networking](https://aws.amazon.com/about-aws/whats-new/2026/04/amazon-eks-hybrid-nodes-gateway/)
  * Amazon EKS now offers the EKS Hybrid Nodes gateway, which automates networking between your EKS cluster VPC and Kubernetes Pods running on EKS Hybrid Nodes, eliminating the need for complex on-premises routing coordination.
  * The open-source gateway is deployed via Helm, available across all EKS Hybrid Nodes regions at no additional charge, and automatically manages VPC routes as workloads scale.

* [Amazon EKS enhances cluster governance with new IAM condition keys](https://aws.amazon.com/about-aws/whats-new/2026/04/amazon-eks-iam-condition-keys/)
  * Amazon EKS now supports seven additional IAM condition keys for cluster creation and configuration APIs, enabling organizations to enforce governance policies for API endpoint access, encryption settings, Kubernetes versions, and deletion protection.
  * These condition keys integrate with AWS Organizations Service Control Policies (SCPs) to enable centralized governance across accounts without manual intervention, available across all EKS regions at no extra cost.

* [AWS Neuron announces support for Dynamic Resource Allocation with Amazon EKS](https://aws.amazon.com/about-aws/whats-new/2026/03/neuron-eks-dra-support/)
  * AWS introduces the Neuron Dynamic Resource Allocation (DRA) driver for EKS, enabling Kubernetes-native hardware-aware scheduling for AWS Trainium-based instances without requiring custom scheduler extensions.
  * The driver allows infrastructure teams to define reusable device templates that ML engineers can consume without understanding underlying hardware topology, enabling efficient resource sharing across multiple workloads on shared nodes.

* [Amazon EKS managed node groups now support EC2 Auto Scaling warm pools](https://aws.amazon.com/about-aws/whats-new/2026/04/amazon-eks-managed-node-groups-ec2-warm-pools/)
  * Amazon EKS managed node groups now support Auto Scaling warm pools, allowing you to maintain pre-initialized EC2 instances alongside your Auto Scaling group that are ready to join the cluster immediately during scale-out events.
  * This significantly reduces provisioning delays for applications with burst traffic, time-sensitive workloads, or complex initialization requirements by eliminating full cold-start initialization during scaling.

* [Amazon EKS now supports one-click cluster access through CloudShell](https://aws.amazon.com/about-aws/whats-new/2026/04/amazon-eks-one-click-cluster-access/)
  * Amazon EKS now provides one-click cluster access directly from the AWS Management Console through AWS CloudShell, eliminating the need to install and configure kubectl, AWS CLI, or kubeconfig files locally.
  * This removes setup friction for developers and operators who need quick access to troubleshoot issues or manage cluster resources from any browser without local tooling.

* [Announcing Kubernetes Dynamic Resource Allocation for Elastic Fabric Adapter](https://aws.amazon.com/about-aws/whats-new/2026/05/kubernetes-dra-elastic-fabric-adapter/)
  * Amazon EKS now supports Dynamic Resource Allocation (DRA) for Elastic Fabric Adapter (EFA), enabling topology-aware allocation of high-performance network interfaces for AI, ML, and HPC workloads.
  * DRA for EFA maximizes network interface utilization and ensures data flows through the most efficient paths to accelerators, improving performance for tightly coupled distributed training and inference workloads.

* [**Blog**] [Implement SPIFFE/SPIRE authorization on Amazon EKS](https://aws.amazon.com/blogs/containers/implement-spiffe-spire-authorization-on-amazon-eks/)

## Community news and articles

* [Kubernetes v1.36: ハル (Haru)](https://kubernetes.io/blog/2026/04/22/kubernetes-v1-36-release/)
  * Kubernetes v1.36 "Haru" (released April 22, 2026) delivers 70 enhancements: 18 graduating to Stable, 25 entering Beta, and 25 entering Alpha.
  * Key highlights include fine-grained kubelet API authorization graduating to GA for improved least-privilege node security, resource health status reporting moving to Beta enabling diagnosis of Pod crashes caused by hardware failures via `kubectl describe pod`, and improved GPU scheduling support for AI workloads.

* [Gateway API v1.5: Moving features to Stable](https://kubernetes.io/blog/2026/04/21/gateway-api-v1-5/)
  * Gateway API v1.5 promotes six widely-requested Experimental features to Standard (GA): ListenerSet, TLSRoute, HTTPRoute CORS Filter, Client Certificate Validation, Certificate Selection for Gateway TLS Origination, and ReferenceGrant.
  * ListenerSet enables independent listener definitions that can be merged onto a Gateway—solving multi-tenant coordination challenges and supporting 64+ listeners per Gateway—making this the project's biggest release to date.

* [Announcing the AI Gateway Working Group](https://kubernetes.io/blog/2026/03/09/announcing-ai-gateway-wg/)
  * The Kubernetes community has formed a new AI Gateway Working Group to define standards for routing, load balancing, and managing traffic to AI inference workloads within Kubernetes clusters.
  * The working group aims to extend Gateway API with AI-specific capabilities such as model routing, token-based rate limiting, and semantic caching to address the unique traffic patterns of LLM inference services.

## Open source projects

* [Agent Sandbox](https://github.com/kubernetes-sigs/agent-sandbox)
  * Agent Sandbox is a Kubernetes SIG Apps project that introduces a declarative CRD-based API for managing long-running, stateful, singleton workloads—filling a gap that Deployments and StatefulSets don't address well for AI agent runtimes, coding agents, and persistent development environments.
  * Each sandbox provides a stable identity, optional persistent storage, and a lightweight single-container VM-like experience built on Kubernetes primitives, making it straightforward to run AI agents that need to write code, execute commands, and retain state across multiple turns.
